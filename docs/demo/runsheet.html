Demo runsheet · ~30 minutes

EPM Build From Zero

Start with an empty database and build a project up to recorded progress and a disbursed payment certificate, so every figure on screen has a visible origin. Nothing is loaded from a fixture; nothing is typed twice.

workspace→ project→ contract→ bill of quantities→ schedule→ link→ progress→ budget→ certificate→ three desks

The demo lands on two numbers, and both are checkable in your head

Four bill items weighted 40 / 30 / 20 / 10, with the first activity complete and the second half done. Then one certificate for exactly what was earned, less a tenth held as retention. Physical progress is what the project card reports; the cost index is what the money says about it.

(40 × 100%) + (30 × 50%) = 55% | 550,000,000 ÷ 495,000,000 = CPI 1.11
What is verified, and what is not

Steps 01–07 carry the original sheet's claim that the sequence was run end to end; steps 01–03 were independently re-run against the API on 2026-09-02 and behaved as written. Steps 08–10 are new and have not been run at all. Their fields, permissions, refusals and arithmetic are read directly from the endpoints (EP-FIN-02, EP-FIN-03, EP-FIN-04) and from Domain/PaymentCertificate and Domain/EarnedValue — the rules say these figures should appear, but nobody has watched them appear. Rehearse the finance act once before presenting, and trust the screen over this sheet.

Before you start

cd api/Epm.Api && dotnet run          # API on :5080
cd web && npm start                    # web on :4300
curl -X POST http://localhost:5080/api/dev/reset

The reset leaves an empty schema. The lookup vocabulary comes back with it, so every dropdown is populated and nothing else is. Do not run load-fixture — that is the opposite of this demo. You want an empty database so the audience watches the data appear.

Present at 1440 or 1280 wide; below 1200px the module rail collapses to icons. A project you create today has no data date set, so “now” falls back to the real date — which is what the planned percentage and the audit-deadline clock are measured against.

Amount = quantity × rate. Weight = the item's amount ÷ this contract's bill total. Weights are rounded by largest remainder so they sum to exactly 100.00 — never 99.99. The denominator is the contract's rows, not the project's; totalling the project and then filtering is the classic version of this bug.

Act two · the money

Everything so far is work. None of it has moved a dinar, and the project card still shows an em dash where the cost index goes. These three steps close that — and they are where the ministry's separation of duties is at its strictest: three desks across two parties, and the party that raises the claim may not audit it.

The ceiling is checked twice

The dash was the point

Before step 10, CPI rendered as an em dash with its reason, not as zero. A screen that shows 0 for a figure it cannot derive teaches the reader to stop trusting it. The same rule governs every tile on this card — and you have just watched one dash become a number by recording the thing it was waiting for.

The module rail now carries a coloured dot per unit, and خط سير المراحل counts more units holding data than it did before the finance steps. All of it derived from row counts, none of it a status anyone set.

If they ask

Why is the financial percentage lower than the physical one?

Because a tenth of the certificate is retention, held until the works are accepted. The contractor has earned 550 million and been paid 495. That gap is the retention doing its job, and it is why certified and paid are two different columns everywhere in this system.

Could one person have done all of that?

No, and the refusals are server-side, not hidden in the interface. Five switches across four personas: the centre defines the workspace, the specialist defines the work, the resident engineer owns the baseline and the claim, and the finance directorate owns the budget and the money. Each refusal you saw is the rule stating itself.

Why does the strip say بدأت and not معتمد?

ملحق الشكل 4 shows 4/8 معتمد. This system has no per-module approval state — it was removed from المسار 1 and المسار 2 at the client's own instruction. Calling a unit approved because it merely holds rows would be a fabricated verdict on the first screen a manager opens, so the strip counts what it can actually know.

Can we change a quantity after this?

Only through a change order, and that is the next demo. The 20% rule is per bill line, measured against the original quantity — and the original is never overwritten. Approving an order changes nothing; applying it moves the quantities, the dates and the penalty baseline.

What happens if a desk sits on the file?

Each stage carries a time cap measured against the data date, and a breach escalates automatically — the مهل التدقيق tab is where that is visible. Since this project has no data date, the clock runs against today, so nothing will have breached during a thirty-minute demo. Say it rather than show it.
