Verification status

Every track on this sheet was run live end to end on 2026-09-09 — T1 through T6, T8, T9 (works, stages 1–5), T9 (supply), T10, T11, T12, T13, and T14's portfolio dashboard — against a real reset-and-build Act A and a real reset-and-fixture Act B, not read off the source alone. Every figure quoted below (55%, CPI 1.11, 42,038,904, the exact refusal and skip-reason strings) was read from the running screen. Three corrections came out of that run and are flagged inline where they land: nu is الجامعة المستنصرية, not النهرين; T12's documents live on PRJ-0279, not PRJ-0439; and T9(works)' Apply step is genuinely blocked for any order that never trips the 20% tier — Order.ApprovedValue is set nowhere in the live code, only in fixture rows, so a freshly-created order can clear all 6 stages and then refuse to apply. File uploads (BOQ Excel, schedule XER, payment-certificate attachments) could not be exercised through the browser in this pass — those three were done via direct API calls carrying the same payload the browser would send, and the result was then read live off the screen.

Both proposal fields (contractor's and RE dept's) can take the same delta — the RE figure is what displays either way. Order 1 arithmetic: 100 units at the original rate = +10,000,000. Order 2: 200 units (the remaining 20% headroom) at the original rate + 50 units at whatever rate-committee fixes.

Click-tested 2026-09-09 — order 1 (the in-tier case) was walked live through all three personas: re-dept stage 1, co-committee stages 2/4/5, back to re-dept for stage 6. Stage 3 skipped automatically, exactly as planned. The wizard fields, the per-stage موافقة action, and the impact summary (+10,000,000, no 20% breach) all matched this sheet exactly.
Apply is blocked for a fresh order — after all 6 stages complete, a further action appears (تطبيق الأمر وإصدار الملحق, owned by re-dept) that actually moves the quantities into the BOQ. It refuses: «لا يمكن التطبيق قبل اعتماد القيمة من لجنة التسعير». Order.ApprovedValue is never assigned anywhere in the live code — only fixture-seeded rows carry it — so an order that never trips the 20% tier (which is most of them) can be walked through every stage but never actually applied in this build. Say so if asked to show the applied contract value; don't attempt order 2, since it would hit the same wall after rate-fixing.
No conflict running order 1 and order 2 back to back on the same contract/line — no gate limits a contract to one change order.
